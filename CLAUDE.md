# Abstract Games Platform

Generic platform for abstract board games (async-vs-human + vs-bot), games added as modular packages.
See PLATFORM_PLAN.md (roadmap) and engine/SPEC.md (game authoring contract).

## Layout
- `legacy/` — the original standalone React prototypes of Oust & Yodd (archived, not part of the live app; both now run as engine modules). See `legacy/README.md`.

## Run / dev
- `./dev.sh` — backend :8000 + frontend :5173 (Vite proxies `/api`); sources gitignored `dev.env` (e.g. `AGP_ADMIN_EMAILS`).
- **Restart the backend after any engine/game change** — the game registry loads game code at startup and is cached (uvicorn runs without --reload).
- Frontend `web/src` edits are live via Vite HMR on :5173 — **no `npm run build` needed in dev** (build only for production/`dist`).
- **Prod-parity check locally:** `cd web && npm run build` then `uvicorn server.app:app --port 8000` — the backend serves the built SPA + `/api` from one origin (it auto-mounts `web/dist` when present), exactly like the Render deploy.
- Stop a server by PORT, never `pkill -f vite|uvicorn` (the pattern matches the bash command itself → exit 144): `kill $(ss -ltnp | grep ':8000 ' | grep -oP 'pid=\K[0-9]+')`.
- **The self-match trap also applies to `pgrep` WAIT-LOOPS** — `until [ "$(pgrep -c -f foo.py)" -lt 1 ]` never exits, because the waiting shell's own command line contains `foo.py`. Wait on a captured PID (`while kill -0 $P`) instead. And a **`nohup` launched from a Bash call inherits that call's *shifted* cwd**, so relative package paths silently resolve wrong — use absolute paths and `python3 -u`.
- Start long-lived servers via the Bash tool's `run_in_background`, not `nohup ... &` in a foreground call.
- **uvicorn/httpx/pyffish live in `.venv`, not system python3** — start the backend with `.venv/bin/python -m uvicorn server.app:app --port <p>` (`python3 -m uvicorn` → "No module named uvicorn").
- If `ss -ltnp` shows a port **with no `users:(...)`/`pid=`** (and `lsof`/`fuser` also find nothing), it's a Windows-side listener that WSL forwards — you cannot kill it. Confirm it isn't ours (`curl /api/games` 404s) and just use another port.

## Engine / authoring a game
- A game = `engine/games/<uid>/{manifest.json, game.py}` (game.py = one `agp.game.Game` subclass; uid comes from manifest — don't hardcode it in the class).
- Validate/iterate: `cd engine && PYTHONPATH=. python3 -m agp.cli validate|playtest|render|pack games/<uid>`.
- Moves are strings: `>`-separated cell-id path (`"2,1>3,4>5,6"`), optional `=CHOICE` suffix (promotion). Cells: `"col,row"` square, `"q,r"` axial hex.
- **Guarantee termination** (conformance plays random games to a terminal): add no-progress + hard-ply-cap draw rules for games that could loop. **Derive the cap from the game's own bound and NEVER shrink it to fit the harness** — conformance's random-game ceiling is 3000 moves, and a game with a heavy random-play tail (drop games recycle material: random Hex Shogi runs to ~8,500 plies while real play ends in a few hundred) declares `max_random_plies` in its manifest instead. Set `max_random_plies` **below** the game's own `PLY_CAP` on purpose, so a termination regression fails LOUDLY as "did not terminate" rather than being absorbed into a silent cap draw.
- Optional hooks: `describe_move` (move-log notation), manifest `category` (lobby grouping — **`GamePicker` groups by EXACT string, so a near-miss ("Territory / area control" vs the real "Territory") silently exiles the game into a singleton lobby group.** Check a new manifest's category against the existing counts before merging). "Win as event" games store the result in state (e.g. Oust/chess `winner`), not inferred from the board.
- **Scored games: a genuine tie is an honest DRAW** (`winner=None` / `returns [0,0]`), NEVER a fabricated tiebreak "that should be unreachable" — it usually IS reachable (e.g. an early symmetric double-pass) and a fake winner is an exploitable bug. "Draws are impossible" claims usually mean *full* boards; still handle the reachable tie.
- Rule variants / board sizes → manifest `options` (auto-rendered as dropdowns); make a separate package only for a genuinely distinct game.
- Ship a **`rules.md`** (one page, rules *as implemented* — the local source of truth) in each game package. The web UI shows it via a "Rules" button and serves it at `/api/games/<uid>/rules`; `manifest.bgg_url` becomes the "official source" link. Supported Markdown (`web/src/Markdown.jsx`): headings, `**bold**`/`*italic*`/`***both***`/`` `code` ``, **NESTED emphasis** (`**a quint of *your* colour**` — the old `[^*]+` pattern failed on any inner `*` and showed the reader raw asterisks in 44 files) and **backslash escapes** (`\*Star` is a real game name; `f8\*D`), `-`/`1.` lists **incl. hard-wrapped items**, `[links](url)` (emphasis inside the label works), **GFM pipe tables** (alignment colons honoured; a cell may hold an escaped `\|`), **``` fenced code blocks** (use these for ASCII board diagrams — whitespace is preserved verbatim) and **`>` blockquotes**. Tables and `pre` scroll inside their own container, so a wide table can't stretch the modal.
- The lobby/quick-play game selector is a searchable, category-grouped `GamePicker` (`web/src/`); `manifest.category` and `tags` feed grouping and search.
- Non-cell legal moves (e.g. `"swap"`, `"pass"`) auto-render as action buttons; `=CHOICE` moves show a picker.
- **Hex-chess-family games subclass `agp.hexchesslike.HexChessLike`** (Glinski/McCooey/Shafran/Brusky/de Vasa/Mini Hexchess all do). The ortho/diag/knight offset tables are **byte-identical in axial space for the whole family** — both orientations — so only the pawn (and castling) differ. Seam: `cell_name`, `setup_board`, `is_promo`, `pawn_moves`, `pawn_attackers` (the REVERSE lookup used by check detection — a separate code path from movegen), plus optional `castle_moves`/`update_castling`/`ep_after`/`board_spec` and the on-disk `ep`+`castling` encodings. Canonical move tuple `(frm, to, promo, ep_victim, castle)` and canonical `ep = (victim, (targets…))` — keying e.p. on the VICTIM cell is what lets Shafran's multi-cell e.p. and Brusky's two-forward-direction pawn share one core. **`_draw_reason` lives in the core**, so the 9-occurrence "a decisive result outranks the draw counters" bug cannot regenerate in this family. **Never change a shipped variant's `serialize()` JSON shape** — the server stores state in the DB (`Match.state`), so it breaks in-progress async matches.
- **Chess-family games subclass `agp.chesslike.ChessLike`** (board model, slider/leaper move-gen, attack/check, draws, serialize/render). A variant just sets `WIDTH/HEIGHT`, a `PIECES` movement table (`{letter: (slide_dirs, leap_offsets)}`), `HEAVY` material, `setup_board()`, and four strategies — `PAWN` (`StandardPawn`/`BerolinaPawn`), `PROMOTION` (`LastRankPromotion`/`GrandPromotion`), `CASTLING` (`StandardCastling`/`NoCastling`), and `DROPS` (`NoDrops` default / `CrazyhouseDrops`). See `games/{chess,berolina,grand_chess,los_alamos_chess}` (~40 lines each). Validate new variants with a perft check against known node counts.
- **Drops / off-board reserve** (the first UI capability investment, shipped via Crazyhouse): the `DROPS` strategy adds a per-seat `hands` reserve + a `promoted`-square set to `CState` (both no-op/absent unless `DROPS.enabled`, so the other ~20 variants are byte-identical). A drop move is the string `"L@c,r"`; captures bank into the reserve; `render()` emits `spec.reserve = {seat: {letter: count}}`. **No server change** — the enforced path is `move in legal_moves`. The web `Board.jsx` shows two reserve trays (seat 1 top / seat 0 bottom): click your chip → legal drop targets highlight → click to drop. Reuse this for Shogi (its own `DropRules` for drop-zone/nifu) and the Morris family (different board, custom adjacency). Anchor with python-chess `CrazyhouseBoard` (see `games/crazyhouse/_diff_pychess.py`, manual/one-time).
- **Randomness without a chance node:** roll/deal in `apply_move`/`initial_state` and STORE the outcome in state (the die / dealt cards); set manifest `has_randomness: true`. The generic UI/bot then need no CHANCE handling (EinStein, Onitama). `num_players` is a fixed property read before any state exists, so it can NOT be a manifest option — a variable-player game picks one count (Chinese Checkers is fixed 6-seat).

## Server
- `DATABASE_URL` (default `sqlite:///./agp.db`). Uploads run game code IN-PROCESS (RCE) → gated, closed by default: `AGP_ADMIN_EMAILS` allowlist or `AGP_ALLOW_OPEN_UPLOADS=true`. Real sandbox is deferred.
- Game registry caches at startup; `POST /api/games/upload` hot-reloads it.
- **Schema changes: NO Alembic — `db.init_db()` runs `Base.metadata.create_all` only.** It creates NEW tables but NEVER ALTERs existing ones, so adding a column to `User`/`Match` won't appear on the live Neon DB. Add a NEW table instead (how ratings/deadlines/chat were done), or compute from existing fields (move deadlines derive from `match.updated_at`).
- **Match-completion hooks** (`server/games.py`): `rate_finished_match(db, match)` (Glicko-2, `server/rating.py`) + `forfeit_if_overdue`/`sweep_overdue` (move deadlines) are idempotent and called after `/move`,`/resign`,lobby-load. Ratings/leaderboards/profiles/replay/chat/spectating/quick-pair all live; `match_view` attaches per-seat rating+delta+deadline.

## Known issues — see `KNOWN_ISSUES.md`
- **✅ MCTS bot speed — FIXED (2026-06-26).** `MCTSBot` now takes a `max_time` wall-clock budget (server passes `AGP_BOT_MAX_TIME`, default 3s) + `max_rollout=50` + an optional `game.heuristic(state)` eval at the rollout cutoff (`ChessLike.heuristic` = tanh material balance; draw fallback for games without it). Chess move minutes→~3s. Add a `heuristic` to a `Game` to make its bot stronger — but it **MUST return a LIST of `num_players` payoffs** (same convention as `returns`); a bare float raises `TypeError: 'float' object is not subscriptable` in back-prop (`payoffs[p]`). **Only fires when the rollout cutoff is reached**, so a game shorter than `max_rollout` hides the bug (blokus_duo shipped it) — test with a low `max_rollout=4` to force it. See SPEC.md. Free-tier knob: raise `AGP_BOT_MAX_TIME` env if the bot feels weak.

## Adding games at scale (the "game factory")
- The bundled library (410 games) was largely built by an autonomous loop. `GAME_BACKLOG.md` is the capability map (the abstract-game universe bucketed by the platform primitive each needs); `GAMES_QUEUE.md` is the live status + the merge gate + escalation digest. Read both before a bulk game effort.
- **Session hygiene — clear between waves, don't carry history.** Waves are independent and ALL durable state lives on disk (git commit messages, `GAMES_QUEUE.md` SESSION HANDOFF, `GAME_STATUS.md`, the `game-factory-*`/`platform-direction` memories, this file). So at a **clean checkpoint** (wave committed + pushed + suite green + queue/memory updated + tree clean) a `/clear` loses nothing durable and resets the token cost; a fresh session re-orients in ~2-3 reads (memory auto-loads → read the queue handoff → go). Prefer `/clear` over `/compact` at wave boundaries (compact keeps a summary you don't need); use `/compact` only MID-wave (agents in flight / uncommitted decisions). **Before clearing, PRE-STAGE the next wave in the queue handoff** — the specific games, deduped, with sourced rules — so the next session is a one-line kickoff ("continue the game factory — next wave per the GAMES_QUEUE handoff") and doesn't re-scout.
- The factory is a reusable dynamic **Workflow** (script under the session's `workflows/scripts/game-factory-*.js`): per game, one agent implements the package and a *different* agent adversarially verifies it; the orchestrator owns a deterministic merge gate (auto-merge on a published anchor or a clean independent review; queue only genuine ruleset decisions / new board shapes). See the `game-factory-loop` memory.
- **Anchor chess-family games with perft**; for variants, **python-chess / shakmaty** (install in `.venv`) are gold-standard differential oracles — use them for one-time verification only. **`pyffish` (Fairy-Stockfish bindings, pip-install in `.venv`) is a general oracle for ANY FSF variant** — built-ins (duck, shatar, shogun via `[shogun:crazyhouse]`) and custom rulesets via `pyffish.set_option`/`load_variant_config` on a `variants.ini` block; perft + legal-move differential. (Calling an unloaded custom variant SEGFAULTs — load the config first.) For large shogi, **`hachu` (Debian `apt-get download hachu`, the 0.21 release — the github 0.23 build is buggy)** speaks CECP and differentials Chu/Dai; `@@@@` is its Lion-pass null-move, and feeding an invalid usermove makes it dump its full root move list. **`pentobi` (GPL, github.com/enz/pentobi) is the reference engine for the WHOLE Blokus family** (classic/duo/trigon/junior/nexos/callisto/gembloq): `cmake -B build -DPENTOBI_BUILD_GTP=ON -DPENTOBI_BUILD_GUI=OFF` → `pentobi-gtp` (needs no Qt; **`cmake` is NOT installed and apt needs sudo → `.venv/bin/pip install cmake`**). GTP: `set_game blokus duo` (the FULL name — `duo` alone is rejected), `all_legal <colour>` (duo=`b`/`w`, 4p=`1`..`4`; **multi-line response ended by a blank line** — reading one line silently under-reports), `play`, `final_score` (`0` = draw). Its source is authoritative for geometry/bonuses. Differentials live at `games/{blokus,blokus_duo,blokus_trigon}/_diff_pentobi.py` (env `PENTOBI_GTP`); compare **covered-CELL-SETS, not move strings**, so they survive move-notation changes. **`oppai-rs` (github.com/pointsgame/oppai-rs, AGPL — oracle only, never copy code) is the reference engine for Kropki/Dots**; Rust toolchain installed at `~/.cargo/bin/cargo` (rustup minimal profile, userspace). `games/kropki/_diff_oppai.py` (env `OPPAI_CLI`) emits its own ~90-line Rust harness via `--write-harness`, builds it against the `oppai_field` crate, and compares FULL board state (live/dead dots, paint, base marks) + scores per move. The pointsgame org also ships formally-verified sibling implementations (Agda/Lean) for a second opinion.
- **A SOLVED game is the strongest anchor there is:** if the state space is ≤~1e9 or a published solved value exists, write a one-time full solver (retrograde or memoized negamax) and assert the designer's published game value — this validates the ENTIRE ruleset end-to-end at once (done for Mijnlieff = 2nd-player win via 2.47B-node alpha-beta, Neutreeko = draw / 51-ply / 3.08%-neutral via a 3.4M-position retrograde solve, Soluna, Bobail). One-time (not in the pure-stdlib selftest); freeze the result.
- **Build/QA agents' briefs are often wrong on metadata** (BGG ids, designer/publisher/year): tell every agent "sources override the brief" — they corrected me on Omega/Veletas/Qawale/Neutreeko/Zola this run. Publisher rulebook PDFs are authoritative and reliably fetchable: **nestorgames.com/rulebooks/<NAME>_EN.pdf**, **marksteeregames.com/<Name>_rules.pdf** (MOST Steere sheets use the `_rules` suffix — a few, e.g. `Zola.pdf`, omit it; probe the filename with `curl -o /dev/null -w %{http_code}`. They're Illustrator vector PDFs with NO text layer → `pdftoppm -png -r 200` and READ the figures, which carry setup + worked examples), Cosmoludo/Gigamic/Blue-Orange sheets, spielstein.com (server-rendered), and **BGA's `en.doc.boardgamearena.com/Gamehelp<game>`**. BGG's XML API now 401s — use `api.geekdo.com/api/geekitems`, Wayback, or web search.
- **AbstractPlay `gameslib` (github.com/AbstractPlay/gameslib, MIT — ORACLE ONLY, never copy code) is the multi-game oracle for the Steere/Bolaños-Mures seam** — 277 games, each a runnable rule-ENFORCING implementation. Setup recipe + quirks in the `gameslib-abstractplay-oracle` memory. Run drivers with **`npx ts-node -T`** (transpile-only; plain `ts-node` fails the whole clone on an unrelated `TS2578` in `src/games/_base.ts`). Compare **cell-sets, not move strings**; filter its `moves()` through its own `validateMove`; drive from BOTH sides.
- **But sceptical ≠ assume-wrong: wave 19 found ZERO oracle bugs across four games**, and both agents independently concluded `necklace.ts`'s odd-looking `seen = new Set()` reset is **load-bearing and correct** — it is precisely the bug our own package shipped. A mismatch is a hypothesis about *which side* is wrong, and often it is us. Never patch your code to match the oracle without a primary source, and never dismiss the oracle's strange-looking code without one either.
- **The DEAD-SKIP bug is systemic in `gameslib`, not a one-off:** `minefield.ts` (wave 18), then `clearcut.ts` and `nakatta.ts` (wave 20) all reject the `"pass"` their own `moves()` offers, because `validateMove` falls through to `algebraic2coords("pass")`. It is not merely dead code — a stuck position becomes a **hard deadlock** (`gameover:false`, no playable move), reachable at ~1 in 460 plies. Same coder throughout. **Grep the clone for this shape before differentialling any game with a skip rule.** Wave 20 also found `onager.ts` generating jump chains against the **un-updated board** (the mover's own vacated start square still acts as a jump partner). Oracle trustworthiness is PER GAME: wave 18 = four bugs, wave 19 = zero, wave 20 = three, wave 21 = two. Wave 21's pair: **`slyde.ts` `getGroupSizes` aggregates singletons into a trailing COUNT** and compares it element-wise against real group sizes (`[5,1,1,1]` → `[5,3]`), **flipping the declared winner** on 1.33%/0.73% of 4×4/6×6 finishes — found INDEPENDENTLY by both the builder and QA; and **`hexentafl.ts` `checkEOG` has no no-legal-move case** ⇒ hard deadlock, ~1 in 7,000 plies, the same *family* as the dead-skip but reached differently (that game has no `pass` move at all). `slyde.ts` and `ccorridor.ts` were both checked and are clean of the dead-skip shape.
- **THE PRIMARY SOURCE ITSELF CAN BE WRONG — and you can prove it, but ONLY with a control that PASSES.** Nakatta Pro's Figure 3 marks 7 illegal placements where its own Figure 2 implies 24. What turned "our decoder is broken" into "the sheet is broken" was running the identical pipeline on the sibling **Minefield** sheet and reproducing it **exactly** (13/13). Three-part recipe, in strength order: (1) a **figure-INTERNAL contradiction**, which survives any decoding error — two byte-identical local configurations marked differently cannot both be right under a translation-invariant rule; (2) a passing control on the same template; (3) a **monotonicity refutation** — legality is monotone in the glyph set, so if any closed set reproduces the figure the *maximal* admissible one does; build it and show it does not. Decode by two UNRELATED methods (vector-path parsing vs pixel classification) and have a second agent derive the marks before reading the first's list. Never claim a source defect without the passing control.
- **MAKE THE RIVAL IMPLEMENTATION PLAY THE DISPUTED GAME.** Cairo Corridor's builder justified its placement reading with a piece-count argument ("the restricted reading caps at ~50, stranding 5 pentagons each"); QA refuted it by having AbstractPlay's *restricted* implementation replay our own 60-placement witness — **60/60 accepted, 0 rejected** ⇒ restricted max = open max = 60, so the box contents cannot discriminate at all. The conclusion was still right on other evidence. **A confident FALSE justification for a CORRECT conclusion is still a defect** — it is what the next reader will rely on.
- **WHEN THE ORACLE IS YOUR ONLY TIE-BREAKER, GO LOOK FOR A THIRD IMPLEMENTATION.** heXentafl's two figure ambiguities rested on gameslib agreement — the weakest adjudicator we accept — until QA found **SkudPaiSho** (2019, five years older, independent, and *announced by the designer himself*), whose source names the alternating-triple rule outright. Honestly flagging "decided by oracle agreement" is acceptable; leaving it there when a third implementation exists is not.
- **An oracle is NOT an authority — `gameslib` has 12 known RULE bugs, four of them found in a single wave** (wave 18, in 3 of 4 games: `take.ts` credits total annihilation to the NON-mover; `bamboo.ts`'s `canPlaceAt` tests only the group the new stone joins ⇒ illegal moves on 15% of plies; `minefield.ts` decides wins with 8-adjacency ⇒ wins on purely DIAGONAL chains, and its `validateMove("pass")` always throws ⇒ its skip rule is dead code). **Treat a differential mismatch as a HYPOTHESIS about which side is wrong** and adjudicate with the primary source — for Steere, the PDF **figures**, which print complete legal-move sets and worked examples and so settle interpretive questions outright (Bamboo's one ambiguity was decided by scoring SIX candidate readings against both figures; exactly one survives, and it is not the oracle's). Put "sources override the brief AND the oracle" in every build brief.
- **Ask up front which rule areas the oracle STRUCTURALLY cannot cover** — that is where the defect will be. `gameslib` implements pie rules as a UI-level `flags: ["pie"]` outside the game class (so swap logic gets ZERO differential coverage — narrows' shipped bug was in its pie swap), and several `checkEOG`s have no notion of "no legal move". Cover those areas with constructed inputs and small-board solves instead.
- **For vector rulebooks, `pdftocairo -svg` + parsing the shape paths beats `pdftoppm` + reading pixels** — Atoll's whole board came from 140 parsed disc paths, which also exposed an unstated constraint (N ≡ 3 mod 4). **Check Wayback CDX digests AND fetch the OLD revisions**: Flume's sheet silently gained its anti-mirroring rule in 2022, and Diffusion's superseded 2006 sheet is a different, far more explicit document that settled three open interpretations by name.
- **The NEWEST Wayback capture can PREDATE the current sheet — never treat Wayback as current.** Minefield's live PDF is a silent 2026-05 revision that ADDED THE WHOLE PIE RULE, and the most recent archived capture still holds the old sheet, so the current rules have never been archived anywhere. **Compare the live PDF's md5/ModDate against the newest archived copy**, and diff the *parsed figure geometry* (an artwork byte-size delta is not evidence of a rule change; identical figures + changed prose usually is). Five consecutive waves found an unadvertised Steere revision; two changed a rule.
- **Dedup every candidate first** (`ls engine/games/` + `git cat-file -e HEAD:engine/games/<uid>/game.py`) — the library is 410 games; most famous abstracts already exist. Screen MECHANICAL clones too (read the closest existing game's `rules.md`), not just name collisions.
- **Build agents must verify rules vs authoritative sources and OVERRIDE the brief on any conflict** — the quality backbone (agents corrected briefs ~14× in one run, e.g. Judkins Shogi's back-rank order).
- **A build agent's package files land on disk (and `validate`) BEFORE its completion notification** — launch the QA agent as soon as `games/<uid>/{game.py,manifest.json}` exist, telling it *"the builder may still be writing — read-only analysis first, defer all edits to the end, re-read before editing"*. But **files-present + quiet + `validate` passes is NOT a completion signal** (agents pause minutes mid-thought): never run/trust `selftest.py` or report a defect before the completion notification. **The `DONE` sentinel fixes this and is now proven** (wave 17): require build agents to `touch DONE` as their last action, gate QA's go-live on the sentinel **plus** the completion notification, and **`rm` the sentinels before `git add`** — no shipped package has one.
- **REQUIRE QA TO PIN FILE HASHES TO ITS VERDICT** (`sha256` of every package file). A QA agent may finish and report *before* the sentinel appears, and the builder can then still edit: in wave 18 Bamboo's QA pinned four hashes, the builder afterwards changed `rules.md` only, and comparing hashes caught it — re-pinging QA for that delta alone found a further defect (a `heuristic` docstring overclaiming bot strength while the corrected `rules.md` said the opposite). A verdict covers bytes, not a package name. (Useful companion: to prove an edit is comment/docstring-only, compare the ASTs with docstrings stripped.)
- **A build agent's BACKGROUND job (solver/differential) can finish AFTER the agent stops** — its notification then carries no report and any results-dependent prose it pre-wrote (e.g. a rules.md "solved value" section) may contradict the actual outcome. Check disk + the job's log, then SendMessage-resume the agent with the real numbers to reconcile (bit jul_gonu: pre-written "first-player win" vs actual ban-free DRAW).
- **A piece with a `label` renders as TEXT-ONLY in the seat colour (no disc)** — Board.jsx's deliberate daldos "·" sleeper convention (also sahkku). A 0-`<circle>` board with pieces in `render()` is NOT automatically a render crash; check for label-only pieces before diagnosing.
- **Model-cap ops:** override an agent's model via the Agent tool `model:` (`opus`↔`fable`) when one caps; BOTH can cap at once (a hard stop — stage briefs, relaunch after reset). A killed agent leaves an EMPTY dir (`rmdir`) or a partial package (`rm -rf`) → clean + relaunch fresh; keep a partial ONLY if all 4 files exist AND validate+selftest pass. Build agents occasionally drop scratch files in the repo ROOT — `git status` after a wave and clean them before committing. **A finished agent's leftover background watchers keep re-firing stale completion notifications** long after it reported (wave 18: one agent notified ~8 times with no new information) — `TaskStop` the agent to silence them, and don't re-read a stale report as new.
- **Bulk throughput:** ~3 build agents in parallel; FAST-PATH perft-anchored ChessLike/ShogiLike variants (standard render ⇒ ~nil render-bug risk → commit on the anchor + a `render()` shape probe); BROWSER-VERIFY only custom-render games; BATCH the backend-restart + browser smoke-checks (don't restart per game).
- **Need a NEW `Board.jsx` render primitive?** The orchestrator owns `web/src/Board.jsx` (a render bug white-screens EVERY game): write the opt-in primitive + REGRESSION-CHECK an existing square + cards (Onitama) + polygons game, document the contract in `SPEC.md`, THEN a build agent writes the engine to emit it. Gotcha: on `polygons` boards the inscribed radius `s.r` ≠ half-width — tile/track/notch edge-glyphs use the cell's `hw`/`hh` bounding half-extents to sit on the border.

## Testing
- Engine: `cd engine && PYTHONPATH=. python3 tests/test_games.py`.
- **Per-game `selftest.py`**: a game package may ship `games/<uid>/selftest.py` — a standalone script asserting its correctness anchor (perft / rule positions). `tests/test_games.py::test_package_selftests` runs every one. **Selftests MUST be pure-stdlib** (import only `agp` + their own game; no `python-chess`/numpy) and fast — the suite runs them under system `python3` where pip-only deps are absent.
- **Probe a package outside the CLI:** `from agp.loader import load_from_dir; man, g = load_from_dir(Path("games/<uid>"))` — game classes take NO ctor args (uid comes from the manifest), so instantiating the class directly fails with "takes no arguments". If a board needs a one-off library to build (e.g. PIL image-segmentation), do it OFFLINE and ship the result as `board.json` loaded at runtime (see `games/pex`) so `game.py`/`selftest.py` stay pure-stdlib.
- **Don't trust a piped suite exit code:** `python3 tests/test_games.py | tail` returns the pipe's (tail's) exit, always 0 — run it unpiped to a file with `echo SUITE_EXIT=$?`, or grep for `all tests passed`.
- **The full suite is SLOW** (~8-20 min at 397 games — CPU contention from parallel agents/browser work roughly doubles it; longer still when the CPU isn't turboing). Per-game `validate` + `selftest` is the fast gate; run the full `tests/test_games.py` only as a periodic backstop (unpiped; grep `all tests passed`).
- **Suite per-selftest timeout = 360s and is a HANG GUARD, not a perf gate.** If an UNCHANGED heavy selftest (e.g. shatar's 300 playouts, ~3.5min) suddenly times out, suspect the MACHINE first: WSL cores pinned at base clock (no turbo — Windows power plan/battery) made everything ~2× slower on 2026-07-17. A throttled box also weakens the MCTS bot per wall-second.
- **Don't run package-scanning tools while a build agent is mid-write** — `gen_game_status.py`, the full suite, and a backend restart all break or load partials on a half-written package (missing `manifest.json` → `PackageError`). Run them only when builds are quiet.
- **A FORMAL PROOF IS A BUG DETECTOR, NOT DOCUMENTATION — write the termination/drawlessness proof, then CHECK LIVE POSITIONS AGAINST EACH OF ITS STEPS.** Necklace's builder caught a real, high-frequency move-generation bug (`encloses()` sharing one `seen` set across four flood fills ⇒ false enclosures silently deleting legal moves on **29.2%/48.8%/71.9% of plies at 5×5/7×7/9×9**) *because a position contradicted step 1 of its own drawlessness proof*. **The game's printed figure was completely blind to it** (the illustrated illegal placement, and both full illegal-placement sets, are identical under the bug), so no figure anchor, conformance run or sweep could have found it. Corollary: **a "genuine tie" in a game you believe is drawless is a BUG until proven otherwise** — that builder had nearly shipped the fabricated draw as an honest one.
- **A SIBLING SHEET IS BOTH AN ADJUDICATOR AND A CANDIDATE GAME.** Halfcut's two interpretive cruxes were pinned by *contrast* with the designer's `Clearcut_rules.pdf` (which states the opposite clause) — and fetching it revealed a published game **not in the library**, which then shipped in the same wave. When the cross-sheet technique fires, check whether the other sheet is itself a missing game.
- **When a sheet was NEVER archived, look for OTHER-LANGUAGE editions.** Onager's English rulebook has zero Wayback captures, but its Spanish (2012) and Japanese (2018) editions do — diffing all three exposed a 2018 revision that ADDED a rule, while the superseded Spanish sheet turned out to be the *more explicit* document on the win condition. Cross-language editions substitute for Wayback.
- **When a sheet contradicts itself, CHECK THE DESIGNER'S OTHER SHEETS for the same clause worded better.** Ūnane's win test is symmetric in both colours yet the sheet claims you can win on your opponent's turn; its own Figure 4 kills only 1 of 5 candidate readings. The *Narrows* sheet states the identical clause with the word **"simultaneously"**, proving it is a tie-break awarded to the mover. Same designer, same phrasing, one sheet more explicit.
- **A PUBLISHED NUMBER can anchor a whole ruleset** — and the good ones discriminate violently. Churn's side-5 length measured **7,404 turns vs the designer's "about 7,400"** (0.05%), while a `<=` removal threshold **never terminates** at that size and pre-merge minimisation gives ~660. The same measurement also refuted the *superseded* sheet's "about 8,500" at >5σ. Prefer this to any number of random games.
- **A predicate that is NOT on the legality path is the one nobody tests** — public helpers, `attacked()`-style reverse lookups, diagnostics. Atoll shipped a public `connected_islands()` nothing ever called, carrying a pair-ordering bug. When a bug of some *shape* is fixed, grep for that shape everywhere; it never appears alone.
- **A `heuristic`'s DIRECTION is a separate assertion from its shape** — a sign-flipped eval (bot plays to lose) and a constant-zero eval both pass shape/range/zero-sum/seat-symmetry checks. Assert "the better position scores higher", pinned to measured values.
- **✅ A BROKEN `heuristic()` IS NO LONGER INVISIBLE — fixed 2026-08-05 (wave 22).** `agp/mcts.py::_evaluate` used to swallow every exception (`except Exception: pass` → `[0.0]*n`), so **a heuristic that RAISED was scored as a perfect draw at every cutoff** — indistinguishable from shipping none, while `validate`, conformance and every functional test passed. Now: a raise emits a `HeuristicWarning` (once per game+exception type) and still degrades to a draw so a live match can't crash; a **wrong-shaped return raises immediately** via `agp.mcts.check_payoffs` (it must be a list of `num_players` finite numbers — a bare float previously died in back-prop with a traceback naming neither the game nor the convention). **`conformance` now exercises `heuristic()` at every ply of its first random game**, so `validate` rejects a throwing/mis-shaped eval for every future game; `tests/test_games.py::test_heuristic_failures_are_visible` locks the contract in. **Library re-audit: CLEAN** — `tools/sweep_heuristics.py` (196 of 414 games expose a heuristic; 405 (uid, options) combos, 21,946 calls) found **0 failures**, and the three shipped "indistinguishable from no eval" claims (bamboo, nakatta, blast_radius) return varying zero-sum values, so they are genuine weak-eval measurements, not hidden throws or constants. **The remaining way to be indistinguishable is a CONSTANT eval** (`heuristic=None` and constant-zero reach the identical `[0.0]*n`), so keep asserting DIRECTION against measured values.
- **MEASURE RATES OVER COMPLETE GAMES, NEVER FROM PLY 0.** The rollout-cutoff fire rate at the opening position is not the whole-game rate — slyde's "100% at 12×12" is 46.8% over whole games; another agent nearly reported a builder wrong off an 82.5% ply-0 snapshot that is 5.3% over complete games. This hit **two independent agents in one wave**.
- **CALIBRATE A MEASUREMENT HARNESS ON A KNOWN-GOOD SUBJECT before trusting a null result.** A harness that cannot detect a sign-flip on an already-shipped eval would report "indistinguishable" for anything. Run the A/A null (none vs constant-zero) too and require it near 0.5 — and note that `heuristic=None` and a constant-zero eval reach the *identical* `[0.0]*n` return, so scoring them identically is evidence the harness is plumbed correctly. This is the vacuity audit applied to a measurement instead of a differential.
- **A differential proves nothing about its coordinate mapping without a control that MUST fail** — run a deliberately mirrored/flipped map and require it to diverge. On a symmetric board, position-level move-set comparison can't distinguish them (a rank-flipped Monkey Queen map passed all 79,171 positions; only whole-game replays from the asymmetric start caught it). **But FIRST do the symmetry-group analysis: a control INSIDE the game's automorphism group cannot fail and proves nothing, and a passing one is NOT evidence of a gap.** On an even square board with a checkerboard setup the four parity-PRESERVING elements of D4 are genuine automorphisms of setup *and* geometry-free rules (only the parity-flipping half is a valid control); on a hexhex with an empty start and distance-only rules the whole dihedral group is. Two substitutes that do work: an **adjacency-isomorphism check against the oracle's own graph** (never touches move-gen), and pinning orientation from an **asymmetric printed figure**.
- **Assert the PREMISE a figure relies on, not only the outcome it illustrates.** A figure-derived test constant is a *source transcription*, and a wrong one passes every assertion built on it — Blast Radius read a printed stack height as 3 (it is 2) and its whole Figure-4 test still passed. The discriminators are the figure's preconditions (is the board saturated? is the other side forced onto one cell?), which a mis-transcription breaks first. Same shape as a vacuous render assertion (`[o]*h == [o]` is trivially true while every stack is height 1).
- **When ONE TURN places several stones (or cascades), the win check must consider EVERY placed stone's group** — and the selftest must cover each stone being the decisive one, in each order. Hexagonal Y's checked only the clicked stone; random play reaches the other order ~0.4% of the time (5/1,380 games), so no sweep finds it.
- **Prefer proving a rule VACUOUS to implementing it defensively — then test it on constructed inputs.** Three sheet clauses dissolved in one wave (an "antipode already occupied" case that cannot arise; a ground-zero exception unreachable under a separation invariant; a turn-skip clause that never fires). **Because random play can never reach a vacuous clause, conformance/differentials/sweeps all skip it** — test it exhaustively on synthetic inputs instead (590,812 board×player pairs for Clusterfuss's skip clause).
- **Exhaustively solving the SMALLEST legal board is the cheapest strong termination anchor** — Bounce's 4×4 (29,602 positions, seconds, with an on-line repetition assertion) proved cycle-freedom, drawlessness AND yielded a game value at once. Available to any game with a board-size option; strictly better than any number of random games. **But the smallest board can be STRUCTURALLY UNABLE to exhibit a bug**, and then your strongest anchor is blind to exactly the case that is wrong: Take's `before_other > 1` mutant survived the whole selftest — a real reachable bug (capturing the opponent's LAST stone would not end the game ⇒ empty `legal_moves` on a non-terminal state, breaking the no-stuck invariant, 15 hits in 2,500 side-3 games) — because that case is *provably unreachable* on the side-2 board the exhaustive solve covers. **Pair the small-board solve with a directed search at a real size.**
- **MEASURE an anchor's DISCRIMINATING POWER; don't assume it.** Minefield's Figure 3 kills 9 of 12 wrong glyph-set variants but is **blind to three** — including tall-orientation-only switches, and Figure 2 prints ONLY the tall orientations, so a literal transcription of the artwork would pass the figure check. Enumerate the wrong variants your anchor is supposed to exclude, count how many it actually kills, and cover the gap deliberately. This is the sharp form of "assert the premise": quantify what the anchor CANNOT catch.
- **A LEMMA'S TEST MUST COVER THE LEMMA'S WHOLE DOMAIN — check the domain, not just the claim.** Slyde's anti-mirroring termination lemma ("no state change ever leaves the position symmetric") was verified exhaustively over 65,536 positions — but `is_symmetric` is an **OR over two axes**, so the test never saw the 65,280 top-bottom-only positions, **half the domain of the lemma it was proving**, and that lemma is the *only* termination evidence for the default-on rule (the exhaustive solve runs with the rule OFF). Widened to all 130,816 positions / 2,093,056 toggles. When a predicate is a disjunction, enumerate each disjunct's domain and prove the union is covered.
- **A vacuous assertion and the bug it hides are often the SAME mistake written twice.** Narrows' pie swap inverted every colour name in the board caption — announcing the WRONG COLOUR AS WINNER for the rest of any game where the pie was taken (offered every game) — and the selftest's only caption assertion, `caption.startswith(("Black","White")[s.winner])`, encoded the identical wrong mapping, so it could never fail. **Pin an assertion to ground truth OUTSIDE the engine** (the owner of a figure's printed corner stone), never to the engine's own derived naming. **This shape recurred TWICE in wave 20**: Onager's `SEAT_NAMES` tuple was never pinned to anything, so swapping it announced **the wrong winner** while all 21 tests passed; Yonmoque's `five`/`stuck` captions name the loser via an inverted index that no test asserted, and that mutant survived the selftest, `validate`, conformance, the render sweep **and both differentials**. A naming constant no test pins is the bug. **It recurred TWICE MORE in wave 21 — 5th and 6th instances, making it the single most reliable defect in the library**: cairo_corridor's `SEAT_NAMES[s.to_move]` → `[1 - s.to_move]` announces the **wrong player to move on every ply of every game** (its *terminal* caption was pinned; the in-play one was not), and nakatta_pro's `edge = "top–bottom" if s.to_move == BLACK else "left–right"` mutant **survived all 50,495 checks** — a board telling Black to aim at the *white* edges. **Put a caption/seat-name mutant in every QA brief by default, and pin BOTH the in-play and terminal captions.**
- **A REDUNDANT RULE MAKES ITS FIGURE ANCHOR BLIND.** Clearcut's removal clause ("remove the two enemy checkers") is provably equivalent to Halfcut's ("remove those in smaller groups") *given* its stricter legality rule — so its Figures 6a/6b **cannot discriminate the two removal semantics at all**, and one other figure is the only discriminator. Prove the redundancy, then state which anchor it kills.
- **Legality invariance limits what a coordinate control can prove.** If the *legality* relation is D4-invariant (common for colour-symmetric placement games), a transposed map **cannot diverge on move sets — only on winner attribution**; a control compared on moves alone falsely passes. When the whole group is an automorphism of the tile map *and* every rule (Yonmoque), an orientation error is **unobservable** — that is a lemma to assert, not a gap to close.
- **Measure a `heuristic` with the CONSUMER that will use it.** A directionally-correct eval can still be worthless: Blast Radius's looked good at 1-ply greedy (0.61 vs 0.34 flipped) but was statistically indistinguishable from no eval through `MCTSBot` (0.500 head-to-head vs constant-zero). Don't let greedy numbers in `rules.md` read as bot strength; shipping NO heuristic with the measurement that justifies it (Clusterfuss) is the honest form.
- **Check each win condition's REACHABILITY under random play before trusting sweep coverage** — 6,000/6,000 random Monkey Queen games ended by regicide and never by stuck-loss, so the differential, `validate` and conformance all skipped half the rules; `selftest.py` was their only coverage.
- **Derive a "provably unreachable" bound from named factors in code, never a pinned constant** — three waves running it was off by one (a swap ply that places no stone; a game-ENDING capture that breaks the "material stays ≥ 4" premise). One was reachable in normal play.
- **Mutation harnesses give WRONG verdicts FOUR ways** — (a) two mutants of equal byte length + a stale `__pycache__` re-runs the *previous* mutant (purge it, `PYTHONDONTWRITEBYTECODE=1`); (b) a whitespace-no-op mutant reads as a false SURVIVOR (fingerprint each mutant); (c) two concurrent runs sharing one mutation root make verdicts flip (per-PID root); (d) **a package selftest does `sys.path.insert(0, parents[2])` + `from games.<uid>.game import …`, so staging a mutant in a FLAT scratch dir lets the import fall through to `PYTHONPATH=engine` and execute the REAL file — every mutant then reads as surviving.** Stage each mutant as `<root>/games/<uid>/` and **assert `g.__file__` is inside the mutant root** before trusting any verdict. Classify "selftest failed ⇒ died" BEFORE consulting any canary, or genuine kills on rarely-reached paths get mislabelled as no-ops. **(e) A SEMANTIC no-op that a byte fingerprint CANNOT catch** — e.g. hoisting a disjunct in a pure disjunction, or a `for…else: pass` — reads as a survivor though the bytes differ; triage every survivor by proving equivalence (heXentafl's was proved a no-op over 597,536 states), never by assuming it.
- **"Win as event" + selftests:** `winner` is set only inside `apply_move`, so `is_terminal` is False on a hand-built no-move/stuck position. Test stuck/annihilation wins by REACHING them via `apply_move`, not by constructing the dead state.
- **Restart the backend to pick up a NEW game** (don't trust auto-reload for new packages). Kill STRICTLY by port; do NOT `ps`/`grep`/`pkill` for `uvicorn server.app` — your own restart command's line contains that string, so the match kills your shell (exit 143/144). Then start uvicorn via `run_in_background` with no grep.
- Backend via `TestClient`: call `server.db.init_db()` first (bare TestClient skips the startup lifespan → no tables). Use `httpx` in `.venv` (not `requests`).
- **A DECISIVE RESULT MUST OUTRANK THE DRAW COUNTERS — test this in every new chess/shogi-family game.** Found in **8 independent places** (2026-07-26): `agp/chesslike.py` (63 variants), glinski/mccooey/shafran as shipped, and caught during build/QA in brusky/starchess/mini_hexchess/hex_shogi_91. The shape is always the same — `_draw_reason`/`_draw` consulted BEFORE the no-legal-move check, so a checkmate delivered on the 100th reversible ply (or in a thrice-repeated position, or at the ply cap) scores 0-0. It propagates by template: every hex chess was written from Gliński, which had it. **Random play will NOT find it** — one QA pass with the general "is any cap outcome-load-bearing?" check in its brief still missed it. The concrete test: play random games to a decisive terminal, then re-score THAT SAME position with each counter tripped (`dataclasses.replace(s, halfmove=100)`, `ply=10**9`, a poisoned `reps`) and assert the decisive result survives. Note Gliński needs the wider form — its stalemate is a *scored* 3/4-1/4 result, so BOTH no-move outcomes must outrank the counters.
- **A selftest that patches a module constant is probably VACUOUS.** `load_from_dir` imports `game.py` under a SYNTHETIC module name (`_agp_game_<hash>`), so `import games.<uid>.game as G; G.PLY_CAP = x` patches a *different module object* than the one running — the test then compares a game to itself and proves nothing (shipped in hex_shogi_91's ply-cap "proof"). Resolve the live module with `sys.modules[type(g).__module__]`, and **assert the patch actually bites** (set it to an absurd value and check the behaviour changes) so it can't silently regress. Patching an *instance* attribute (`G = SomeGame(); G.FLYING = False`) is fine — that's the object under test.
- **The `serialize`/`deserialize` round-trip test is VACUOUS unless it compares STATES.** `assert serialize(deserialize(d)) == d` cannot see a dropped field: `deserialize` reads optional keys as `.get(key, default)`, so a field `serialize()` stops emitting simply re-defaults on the way in and is re-omitted on the way out — equality still holds. Compare the **state objects** (`deserialize(serialize(s)) == s`), assert the exact key set, and sweep a whole game so every shape of every field is covered. Found INDEPENDENTLY IN THREE PACKAGES IN ONE WAVE (attangle dropping `stock`/`variant`, abande dropping `passes`, fendo dropping any of six fields), every one caught only by mutation testing — so assume a new package has it. The real-world failure is invisible locally and severe in production: the server reloads state from `Match.state` every turn, so hotseat and vs-bot (in-memory) look perfect while an **async match silently breaks** — a dropped `passes` counter can never accumulate two passes, making the game literally unendable.
- **Behaviour-preserving refactor = SNAPSHOT + DIFFERENTIAL, and the harness must cover the WHOLE public surface.** Before touching a working game, copy its `game.py`+`manifest.json` to a scratch dir, load the snapshot under its own module name (`importlib` + `sys.modules[name] = mod` before `exec_module`, or dataclasses crash), then play IDENTICAL random games through old and new. Compare `legal_moves`, **`describe_move` for every move**, `is_terminal`, `returns`, `serialize()` and the render caption at every ply. **Omitting one surface lets a change through silently** — my first version skipped `describe_move`, and the hexchesslike core quietly changed move-log notation across six games (added check marks, dropped " e.p.", would have destroyed two games' castling notation) until a build agent noticed. Reusable harness: `scratchpad/hexrefactor/diff_old_new.py`. **Random play rarely reaches castling or e.p.** — add targeted sweeps for those, or a real divergence passes both the differential AND a 900-check selftest (it did). **Keep each package's `selftest.py` UNMODIFIED** so the evidence stays independent — that means preserving the module's PUBLIC SURFACE (selftests import `GState`, `cell_name`, `ORTHO`/`DIAG`/`KNIGHT`, `on_board`, `CELLS`, `PLY_CAP`, …), re-exporting from the core where needed. **Never change a shipped game's `serialize()` JSON shape** — the server stores state in the DB (`Match.state`), so it breaks in-progress async matches.
- **A shared core is worth it mostly for the bugs it makes IMPOSSIBLE, not the lines it saves.** Extracting `hexchesslike` (3,179→2,030 lines of game code + a 527-line core) immediately surfaced two real shipped bugs — McCooey's phantom e.p. and de_vasa missing the decisive-outranks-counters guard (9th instance) — because unifying the representation made the old inconsistency inexpressible. Expect the same when extracting any family core.
- **A game with a board-SIZE option must assert `render()`'s DECLARED dimensions for EVERY size.** `Board.jsx` builds its clickable cell set from `board.width/height` (or hex `size`/`cells`) and joins pieces by cell id, so a piece outside the declared board is **silently dropped — no crash, no warning, the stone simply isn't there**. A `render()` that hard-codes the default size therefore swallows the outer files/ranks of every larger board. The default size hides it, and a per-size check on a *freshly initialised* state is **vacuous** (no pieces yet) — reach a FAR-CORNER position through `apply_move` first. Found as a surviving mutant in taiji (wave 14). Library sweep: `cd engine && PYTHONPATH=. python3 tools/sweep_render_bounds.py` — plays random plies under the default options *and* each single-axis option variation, asserting every rendered piece lies inside the declared board. **Currently CLEAN: 0 failures over 721 (uid, options) combinations / 385 games**, and the sweep is proven non-vacuous (it catches a hard-coded-9x9 mutant on taiji's 11x11 board at ply 1). Re-run it after touching any `render()` or adding a size option.
- **RenderSpec-format bugs are INVISIBLE to `validate`/selftest** (those test the Python game logic, not `Board.jsx`) — a 100%-logic-correct game can still white-screen-crash the board. **Browser-verify EVERY new game** (a 0-nodes / blank page after START = a render crash; the lobby still renders, so it's game-specific). Diagnose via `render(initial_state())['board']` vs `web/src/Board.jsx`.
- Browser checks use pinchtab: click custom buttons by **ref**; click SVG board cells via `pinchtab click --css '[data-cell="c,r"]' --mode dom` (the flag is `--css`, not `--selector`) and non-a11y SVG elements (wall ghosts, cards) via a class selector with `--mode dom`; coordinate clicks are flaky — verify with a screenshot.
- pinchtab session: `export PINCHTAB_SESSION=$(pinchtab session create --agent-id <id> | tail -1)` — all commands then share that tab. Read the move-log/DOM with `pinchtab eval --json '<js>'` (a screenshot goes byte-stale right after a click → re-shoot or use eval). Selecting a game card: search substrings match many cards, so pick by exact title over `button.game-card-main` via eval, not blind index. **Sessions expire on long runs** — recreate with `pinchtab session create` on a `401 bad_session`. **In Quick Play you must click the game CARD to select it BEFORE hotseat/START**, else it launches the default game (search by a unique term — e.g. "Baduk" for Go). `pinchtab screenshot` has **no `--out` flag** — it writes `screenshot-<ts>.jpg` into the cwd, and the Bash tool resets cwd after the call, so `cd <scratchpad> && pinchtab screenshot` then read the newest file. Typing into the search box needs the React native-setter trick: `Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype,"value").set.call(input, text)` then dispatch `new Event("input",{bubbles:true})`.
- **Stale-bundle false alarm (bit 3× in one session):** the browser caches `index.html` pointing at an OLD hashed bundle, so a NEW frontend feature looks completely broken (e.g. palette trays absent, every move rendering as an action button) while the code is fine. Check what actually loaded — `pinchtab eval 'performance.getEntriesByType("resource").filter(e=>e.name.includes(".js")).map(e=>e.name.split("/").pop())'` — vs `ls web/dist/assets/*.js`; fix with a cache-busting `?cb=$RANDOM` nav. Suspect this BEFORE suspecting the game. (`npm run build` first: uvicorn serves `web/dist`, mounted at startup.)
- **Simulating hover for React:** `el.dispatchEvent(new MouseEvent("mouseover",{bubbles:true}))` triggers `onMouseEnter` — but adding `relatedTarget` breaks it (React reads it as movement *within* the element), and reading the DOM in the SAME `eval` sees the pre-render state. Dispatch and assert in SEPARATE `eval` calls.
- **pinchtab IDPI self-false-positive:** the injection scanner FALSE-POSITIVES on our OWN lobby text (game descriptions trip jailbreak/urgency heuristics) → `snap`/`text`/`find` return 403/timeout. Use `screenshot` (pixels, bypasses the content scanner) for visual checks + CSS/`text:` selectors for clicks. The instance is also flaky (`context deadline exceeded` → just retry). No hotseat deep-link — only `?match=<id>`; reach a board via QuickPlay (click the CARD) or log in + open a match.
- **pinchtab external sites:** navigation is gated by an allowlist (`~/.pinchtab/config.json` → `security.allowedDomains`; `403 IDPI: Domain not in allowlist` if missing). The hosted apps (`abstract-games.onrender.com`, `gamefinder-seven.vercel.app`, `generic-poker.onrender.com`, `erikbar.duckdns.org`) are allowlisted for UI testing — `pinchtab server restart` after editing the list. Otherwise verify a live site with `curl`.

## Conventions
- Frontend: one generic `Board` renderer; all board types (`square`/`hex`/`polygons`) go through a unified polygon shape model — `polygons` games supply each cell's vertices as **`board.cells` = a LIST of `{id, points}`** (NOT a dict; vertex key is `points` not `polygon` — getting it wrong crashes the renderer; see SPEC.md). No per-game UI. Seat colors in `web/src/colors.js`.
- **RenderSpec capabilities (opt-in, generic; all 7 backlog UI gaps shipped, plus 4 later primitives — see `GAME_STATUS.md`):** `reserve` trays + click-to-drop (move `"L@c,r"`); **>2-seat** (6 colours in `colors.js`; QuickPlay seats `view.num_players` — MCTS already backs up per-player payoffs, no engine change); `board.lines` (under-cell grooves) & `board.overlay` (over-cell lines, e.g. TwixT bridges), both in cell-coord space; `board.tints` (`{cellId: colour}` terrain/edges); `board.walls` (`{h,v}` groove slots → ghost-click placement, Quoridor); `piece.stack: [owner,…]` (tower glyph, Lasca); `board.cards` (movement-pattern strip, Onitama);
